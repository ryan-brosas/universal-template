Code-quality enforcement philosophy (from scarywood75 + Tom, Discord 7/19/26): 1) Anything mechanical/predictable/deterministic — create TESTS for it (exposed functions not used elsewhere, non-existent consts, unused imports). 2) Detect duplicates with semantic comparison — measure how far one function is from another; near-identical = duplicate. 3) The goal is to REMOVE as much responsibility from the LLM as possible, which tends to forget and makes mistakes. 4) Use 'quality packs' — one universal quality pack across all languages + language-dependent ones. 5) KEY: prompting for something that can be mechanically enforced is USELESS. Example: to force agents to use the web, create a GATE that does not allow them to go further until they've called the researcher agent — because telling the agent to research by prompting doesn't consistently work, but the gate cannot be bypassed. 6) 'Given enough attempts, LLM has no choice but to improve the code.' This is the core of Pillar 2: enforce outcomes mechanically (tests, gates, CI checks), not via prompting or restrictive prose.
