**Flow:** reset (fresh LMMAgent with CODE_AGENT_PROMPT) → task+screenshot as first user message → per-step: generate → sentinel check → extract fence → execute via controller (bash timeout=30; python no explicit timeout) → formatted result back as user message → repeat until sentinel or budget out → summary generated by a SEPARATE one-shot summarizer agent (CODE_SUMMARY_AGENT_PROMPT, ≤150 words, factual tone) → report.
**Invariant:** (1) Steps do NOT share state — every snippet must be standalone ("Code from each step does NOT persist", prompt :171); verification loops must re-inspect files each step. (2) DONE requires a final print of modified-file contents (prompt :220-227) so the worker can verify. (3) The exhaustion check keys off `"completion_reason" not in locals()` — a port that initializes the variable up front silently breaks this arm. (4) temperature is hardcoded 1 for the coding loop regardless of engine params. (5) Empty response RAISES (unlike call_llm_safe's "" contract elsewhere) because an empty step cannot make progress.

## Verdict
Adopt sentinel-based budget loops with a separate summarizer and stateless steps; adapt budget size and the DONE-print requirement to your harness; omit the locals()-check idiom in favor of an explicit flag IF you also fix the exhaustion arm consciously. Bash gets a 30s cap; python does not — decide deliberately when porting.
