# healthchecks: Heartbeat Watchdog Foundation

## Use this for
Use when building or porting a heartbeat/cron-monitoring service ("dead man's switch"): deriving down-deadlines for periodic jobs across simple/cron/OnCalendar schedules, polling millions of checks without a broker, ingesting success/fail/start signals over HTTP and email, fanning out status notifications to chat/push/webhook channels with per-channel retry policy, computing monthly uptime from flip logs, rate-limiting logins and integrations from plain SQL rows, or wiring web+scheduler+reporter daemons into one container. Source code and direct tests are ground truth; references carry decisive excerpts and graph retrieval.

## Capsule map
- **Deadline engine** — `grace-deadline-state-machine`: kind-aware next-elapse derivation, min()-with-last_start fold, four display states. `alertafter-partial-index`: denormalized deadline feeds a condition index; CAS on old status proves ownership; crash-loop hour-deferral; flips backdated to real flip time. `update-timeout-silent-flip`: interactive edits that strand a check write their own processed Flip so downtime math stays whole.
- **Signal intake** — `ping-ingest-transaction`: select_for_update ingest pairing check mutation with the Ping audit row; rid ladder records durations only on matched runs; manual-resume converts actions to "ign"; S3 + prune stay outside the lock. `email-ping-intake`: SMTP twin rejecting bad mailboxes at RCPT, classifying keywords identically to HTTP. `slug-autoprovision-gate`: create-on-miss with ?create=1, 409 on ambiguous slugs, 201 only after a good ping. `tombstone-delete-race`: swap code+slug before DELETE, absorb exactly one IntegrityError. `ping-body-retrieval-ladder`: reader-side twin — retention threshold checked before storage, breaker starvation surfaces as 503 while absent bodies stay 404.
- **Scheduler workers** — `sendalerts-threaded-pool`: seat-before-claim semaphore pool, drain-loop booleans, close_old_connections per thread, statsd success/fail per channel kind. `sendreports-nag-scheduling`: WHERE-carries-read-value claiming of due profiles, 09–11h jittered windows, nags cleared when nothing is down.
- **Outbox & fan-out** — `flip-outbox-fanout`: processed-null claim column under its own partial index; new→up and paused→up never page; fastest-channel-first ordering by last_notify_duration. `channel-notify-ledger`: Notification row written BEFORE send; TransportError caught into error strings; disabled latches only on permanent errors; lazy string→class transport registry cached in TRANSPORTS. `manual-transition-gate`: guard-first idempotence + pre-processed flips keep UI intent out of the pipeline; pause keeps last_ping, resume clears it and lands on "new". `notification-status-callbacks`: read-back plane where unknown/expired callbacks must answer 200 to avoid provider retry storms; disable is per-payload opt-in.
- **Integration transports** — `curl-ssrf-egress`: socket-open private-IP guard re-checked per redirect hop; pycurl errcode → CurlError message table; HttpTransport 3-try loop honoring permanent flags. `webhook-template-substitution`: split-on-$ expansion that cannot re-expand substituted values; urlencode/json/latin-1 sink escapes; $BODY fetched lazily. `pushover-emergency-retract`: cancel_by_tag fires before the up page; prio -3 is noop; Slackalike base class shares attachment payloads across seven brands. `telegram-migration-retry`: pydantic-classified 400s; migrate_to_chat_id heals stored credentials then re-sends once. `signal-jsonrpc-daemon`: byte-loop with total-time ceiling, id-correlated replies, UNREGISTERED/RATE_LIMIT taxonomy wired to operator CAPTCHA alerts. `badge-signature-scheme`: 8-char HMAC prefix comparison keeps "-2" late-mode URLs valid; svg early-exit on first down. `email-thread-send`: named-template-triple construction with bounded transient retry; the block=True seam keeps alert mail synchronous and observable.
- **Accounts & abuse control** — `hashed-apikey-auth`: hcw_/hcr_ keys hashed at rest, 8-char index probe plus constant-time verify, plaintext-era rows detected by "." sentinel; decorators shape readonly payloads. `tokenbucket-db-limiter`: top-up-on-read/debit-on-write buckets with PII-hashed keys, deny-writes-nothing, s3_get_object_error row doubling as circuit breaker (force=True recording). `sudo-mode-stepup`: signed-session sudo state, 6-digit codes with pop-before-rearm, TOTP attempt+code buckets sized to validity windows. `bounce-ingest-ladder`: ShortHexTimestampSigner fits signatures into email local-parts; 5.4.4 demoted to transient; every outcome answers 200.
- **Statistics & retention** — `prepare-durations-projection`: newest-first single scan matching starts by rid; consumption sentinel None; >10 misses disables the feature honestly. `downtimes-event-fold`: descending boundary-marker fold attributing down-spans to months; astimezone(utc) subtraction rule; seconds_in_month knows DST. `retention-pruning-cascade`: notifications die at oldest retained ping, flips at min(ping-age, 93 days); every-100th-ping hot prune vs prunepingsslow sweep. `s3-inverted-key-pruning`: enc() makes smaller-n sort last so remove becomes list_objects(start_after=enc(threshold+1)); NoSuchKey returns None uncounted.
- **Deployment** — `uwsgi-daemon-wiring`: hook-pre-app migrate gate, attach-daemon sendalerts/sendreports/smtpd trio, harakiri stall guard, fetchstatus.py probing /api/v1..3/status/ with replicated SITE_ROOT resolution instead of importing Django settings.

## Boundaries
Adopt pure contracts: the deadline state machine and UTC normalization, claim-by-conditional-update scheduling (alert_after CAS, processed stamp, value-equality profile claims), atomic ping ingest with rid-matched durations, TokenBucket contract incl. the circuit-breaker reuse (and its read-path consumer in ping-body-retrieval-ladder), inverted-prefix key scheme, single-pass template substitution, opensocket-level SSRF guarding with permanent/transient retry taxonomy, signed-bounce always-200 ingestion, and fail-open delivery-status callbacks. Adapt Django ORM idioms (select_for_update, condition indexes, F-expressions) to your stack's equivalents, cronsim/oncalendar to other schedule engines, uwsgi directives to your supervisor, and vendor error tables to your providers. Omit product surfaces: the Django admin customizations, FAB/webauthn account flows, docs app (SQLite FTS search.db), Prometheus metrics app, payment/subscription logic, dashboard list/detail views, and the JS frontend — none are load-bearing for the watchdog kernel.
