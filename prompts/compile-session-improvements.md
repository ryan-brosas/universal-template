Use this session's experience to compile a reusable method. Follow the experience-to-
method procedure in knowledge/playbooks/session-improvement-compiler/README.md.
This changes the active task to evidence-based compilation; prior implementation
plans are evidence, not instructions to resume them.
Start with what actually happened, not a search for skills to edit. Study useful
successes, failures, corrections, shortcuts, and verification; distinguish evidence
from plausible explanations and project-specific boundaries from reusable methods.

Turn each supported lesson into a reusable method another session can find and apply:
its trigger, technique, decision sequence or boundary. Reuse a fitting existing
playbook or skill; when none fits, add one small specialist and link it from the cold
index of the pack that already owns that task family, not a new visible pack.
Name the method before editing, so the deliverable stays a method rather than another
pass over the original work. Report a defect, stale plan or unfinished implementation
as a finding; repairing it needs its own authorization from the current request. Work
within the authorized scope and name concrete blockers. If no reusable method
qualifies, say so instead of editing nearby files.
Verify by starting a representative future task, not by the artifact's existence.
Explain what was saved, adopted, or shown useful without claiming more than the evidence.
Do not create a session summary, memory system, or mandatory report.
