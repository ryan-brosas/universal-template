### Decisive source
```python
// scripts/release.py:104-121 (verbatim)
def has_changes(path: Path, git_hash: GitHash) -> bool:
    """Check if any files changed between current state and git hash"""
    try:
        output = subprocess.run(
            ["git", "diff", "--name-only", git_hash, "--", "."],
            cwd=path, check=True, capture_output=True, text=True,
        )
        changed_files = [Path(f) for f in output.stdout.splitlines()]
        # .md counts as a change: READMEs ship inside the published package
        # (npm tarball / PyPI long_description)
        relevant_files = [f for f in changed_files if f.suffix in [".py", ".ts", ".md"]]
        return len(relevant_files) >= 1
    except subprocess.CalledProcessError:
        return False

// .github/workflows/release.yml:190-198 (verbatim) — npm fail-closed dedup guard
- name: Check if version exists on npm
  run: |
    VERSION=$(jq -r .version package.json)
    if npm view --json | jq -e --arg version "$VERSION" '[.[]][0].versions | contains([$version])'; then
      echo "Version $VERSION already exists on npm"
      exit 1
    fi
```

**Flow:** manual `workflow_dispatch`, owner-gated to modelcontextprotocol → last-release hash via `git rev-list --tags --max-count=1 || echo HEAD~1` → calver version + RELEASE_NOTES.md + per-ecosystem matrices generated by the script (hash arg validated 8–40 hex AND verified present via `git rev-parse --verify`) → update-packages job bumps each changed package's version in-place (tomlkit preserves TOML formatting then runs `uv lock`; package.json rewritten indent=2), commits "Automatic update of packages", tags annotated `$VERSION`, PUSHES THE TAG FIRST → both publish jobs checkout AT THAT TAG; PyPI publishes via pypa/gh-action-pypi-publish with trusted publishing (`id-token: write`) and `skip-existing: true`; npm upgrades the CLI to >=11.5.1 for OIDC trusted publishing, FAILS CLOSED if the version already exists, tests/builds, then `npm publish --access public` with provenance enabled and NO token → create-release runs only when versions actually bumped AND at least one ecosystem succeeded, attaching the notes artifact.
**Invariant:** FIVE load-bearing decisions a porter breaks silently: (1) **suffix filter includes .md** — READMEs ship inside artifacts, so docs-only changes DO release; CI/config changes deliberately DO NOT. (2) **tag-before-publish ordering** — publish jobs build from the pushed tag, making the released tree immutable before any registry sees it. (3) **asymmetric idempotency**: PyPI tolerates re-upload (skip-existing) while npm fails closed on an existing version — keep BOTH halves or re-runs either double-publish or dead-lock. (4) **one shared calver version across same-day releases** is intentional day-granularity idempotency; the npm pre-check compensates for collisions. (5) **OIDC trusted publishing on BOTH ecosystems** — zero long-lived tokens; each package's trusted publisher is bound to this workflow + the `release` environment. Matrices use `fail-fast: false` so one broken package never blocks siblings.

## Verdict
Adopt the shape for any multi-package monorepo: detect releases from payload suffixes against the last tag rather than hand-maintained bump lists; version with calendar granularity shared across the train; push the tag before any publish and build FROM the tag; authenticate registries exclusively via OIDC trusted publishing while encoding each registry's re-run semantics explicitly (tolerant PyPI vs fail-closed npm). Keep the dual-ecosystem Package Protocol so one detection loop feeds both matrices, and regenerate lockfiles inside update_version. Omit nothing from the owner-gate + environment binding if you fork the workflow. No direct-test coverage exists for this seam — treat the YAML itself as the pinned contract.
