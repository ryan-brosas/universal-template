**Flow:** creation → notifier posts open-review card (claim-primary on broadcasts; Open-in-Slack on DMs of fully renderable forms; unsupported_fields ⇒ NEITHER button + inline `_Contains N field(s) that must be completed in the dashboard._` warning; dashboard URL button ALWAYS appended). Claim → claimed_message_blocks (who claimed + dashboard link). Terminal → update_slack_messages_for_task fan-out replaces via chat.update with a section (+View-in-dashboard actions ONLY when a review_url exists — Slack rejects empty actions blocks, so the block is OMITTED not emptied :69-78 test).
**Invariant:** exactly one PRIMARY interaction affordance per card state; the dashboard link is present in EVERY state because it is a URL (uninterceptable, safe post-terminal); terminal surfaces carry zero dispatchable `action_id`s — enforced by a defense-in-depth test that walks the whole block tree asserting no element has an action_id without a url.

## Verdict
Adopt per-state button algebras where each state has ONE primary interaction, links are used for anything that must survive the state change, and terminal replacements are generated by a total function over statuses (with a neutral fallback) that provably emits no interactions. Adapt labels/emoji/statuses. Omit the tree-walk defense test only if your platform makes stray interactions structurally impossible.
