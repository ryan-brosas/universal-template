# Plugin entry registries — how does a Tailwind plugin fan a component registry through include/exclude control without losing layer semantics?

**Source:** daisyUI MIT `master@c6e1800bc15ab0287b8c2b802c126ccee6361beb`; Codebase Memory `ui-daisyui`. **Question:** How do I structure a plugin entry so every base/component/utility item gets the same injection contract, honors user include/exclude lists, and still lets individual items opt out of cascade layers?

## Registry fan-out with per-item injection contract
**Path/Symbol:** `packages/daisyui/index.js:9-68` (default export, `plugin.withOptions`).
**Signature:** `plugin.withOptions((options) => ({ addBase, addComponents, addUtilities, addVariant }) => void, () => ({ theme: { extend: variables } }))`.
**Data Shape:** `imports.js` (generated by `functions/generateImports.js`) exports three registries — `base`, `components`, `utilities` — each `{name → item}` where `item` is a function receiving exactly `{ addBase }` or `{ addComponents | addUtilities, prefix }`. `pluginOptionsHandler(options, addBase, themesObject, version)` returns `{ include?, exclude?, prefix }`.

### Decisive source
```js
const shouldIncludeItem = (name) => {
  if (include && exclude) {
    return include.includes(name) && !exclude.includes(name)
  }
  if (include) return include.includes(name)
  if (exclude) return !exclude.includes(name)
  return true
}

Object.entries(components).forEach(([name, item]) => {
  if (!shouldIncludeItem(name)) return
  item({
    addComponents: (styles) => addComponents(nestCssLayers(styles)),
    prefix,
  })
})

// drawer variants. Can not be nested in layers so defined here
addVariant(`${prefix}is-drawer-close`, `&:where(.${prefix}drawer-toggle:not(:checked) ~ ...)`)
```

**Flow:** options closure runs once per Tailwind build → `pluginOptionsHandler` injects theme CSS via `addBase` and returns filters → the three registries iterate in order (base, components, utilities), skipping filtered names → each item receives a *wrapped* injector so its styles pass through `nestCssLayers` before reaching Tailwind → structural variants that must live outside any layer are registered directly on `addVariant` with the prefix baked into both variant name and selector.
**Invariant:** the include/exclude algebra is include-AND-NOT-exclude when both are present (an item in both lists is excluded); item functions never receive raw Tailwind injectors for components/utilities — always the layer-wrapping closure — and the prefix is threaded into every item plus every hand-written selector.
**Probe:** `packages/daisyui/functions/pluginOptionsHandler.test.js` pins the returned `{include, exclude, prefix}` triple; `bun test functions/pluginOptionsHandler.test.js` GREEN at pin (56-pass run includes it).

## Verdict
Adopt the `{name → item}` registry + uniform injection-contract shape and the include ∧ ¬exclude filter as pure contracts. Adapt registry category names and option vocabulary to your host. Omit daisyUI's specific drawer variants unless you port that component; keep the lesson that variants depending on sibling-selector structure must be registered outside layers.
