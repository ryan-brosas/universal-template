# Human-curated capture loop — checkpoint templates into inbox, promote appends with provenance, state file as interrupt marker

**Source:** pi-memory-extension MIT `main@f3b4377f46d75e49a8dda65d0408aab70d669839`; Codebase Memory `pi-memory-extension`. **Question:** How does session knowledge become durable memory WITHOUT the agent ever auto-writing authoritative files?

## Checkpoint → inbox (`/memory:checkpoint`)
**Path/Symbol:** `pi-memory.ts:481-530` (command handler).
**Signature:** `pi.registerCommand("memory:checkpoint", { handler: async (_args, ctx) => ... })`.
**Data Shape:** writes `inbox/checkpoint-<ISO ts with [:.]→->.md`; template sections Summary / Knowledge to Record (Decisions, Lessons, TODO).

### Decisive source
```ts
if (!cache.workspaceRoot) { ctx.ui.notify("⚠ Checkpoint requires Workspace Memory. Run /memory:init workspace first.", "warn"); return; }
...
const content = [
  `# Checkpoint ${now.toISOString().slice(0, 10)}`,
  ...
  `> Generated by /memory:checkpoint. Use /memory:promote after review.`,
  `## Summary`, `(What was done and why)`,
  `### Decisions`, `- ...`, `### Lessons`, `- ...`, `### TODO`, `- ...`,
].join("\n");
await fs.writeFile(inboxPath, content, "utf-8");
```

**Flow:** require a loaded cache AND an initialized workspace memory → mkdir inbox → write a STRUCTURE-ONLY template (no auto-extracted content).
**Invariant:** The template contains zero model-generated memory — auto-extraction is deliberately absent to avoid misleading memories ("no auto-record" is a design boundary in docs/design.md). Inbox is a staging area that `scanDir` never injects; nothing reaches the prompt until a human promotes it.

## Promote with provenance (`/memory:promote`)
**Path/Symbol:** `pi-memory.ts:533-582` (command handler).
**Signature:** `handler(args: { inboxFile: string; targetDir: string; targetFile: string }, ctx)`.
**Data Shape:** targetDir ∈ {`workspace`, `knowledge`, `user`}; separator `\n\n---\n\n_Promoted from [inbox/<file>]_\n\n`.

### Decisive source
```ts
const separator = `\n\n---\n\n_Promoted from [inbox/${args.inboxFile}]_\n\n`;
await fs.appendFile(targetPath, separator + inboxContent, "utf-8");
await fs.unlink(inboxPath);
```
```ts
} else if (targetDir === "knowledge") {
  targetBase = path.join(cache.globalRoot, "knowledge");
} else if (targetDir === "user") {
  targetBase = path.join(cache.globalRoot, "user");
} else {
  ctx.ui.notify(`❌ Unknown target directory: ${targetDir}`, "error");

```

**Flow:** read inbox file (workspace inbox preferred, global inbox fallback) → resolve target base by allowlist (workspace root | global knowledge | global user) → APPEND `separator + content` to target → unlink the inbox original.
**Invariant:** Append-only promotion preserves prior entries; the provenance separator is part of the contract (audit trail from candidate to authoritative). Unknown target dirs are rejected loudly, never guessed. Inbox file is deleted only AFTER a successful append. Note the asymmetry worth porting consciously: workspace targets need no existence check, but `/memory:init workspace` refuses when `index.md` already exists.

## State file lifecycle (`state/current-task.md`)
**Path/Symbol:** `pi-memory.ts:261-263` (load), `pi-memory.ts:584-597` (`/memory:clear-task`).
**Data Shape:** single file `~/.pi/memory/state/current-task.md`; trimmed content or `""`.

### Decisive source
```ts
const stateRaw = await tryReadFile(statePath);
const stateContent = stateRaw?.trim() ?? "";
```
```ts
await fs.writeFile(taskPath, "", "utf-8");   // /memory:clear-task empties it
```

**Flow:** loaded separately at session start OUTSIDE the merged files cache → injected as its own top-priority section → cleared manually via command after interrupt resolution.
**Invariant:** State is working context, not knowledge — kept out of `cache.files` and never scanned by `scanDir` (`state/` is excluded); clearing means truncate-to-empty, not delete, so the file always exists for the next interrupt.

## Verdict
Adopt the three-phase human-gated loop: structure-only checkpoint template → human edit → allowlisted append-with-provenance promotion + inbox delete. Adopt the separate state-file channel for interrupts. Adapt filenames/timestamps to host conventions. Omit any temptation to auto-distill — that omission IS the design (v3 non-goals list auto-distillation explicitly). No upstream test suite exists; pin behavior to the cited source ranges at port time.
