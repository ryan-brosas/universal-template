# qodana-action: CI-integration suite foundation

## Use this for
Use when porting analyzer/tool integration into GitHub Actions, GitLab CI, or Azure DevOps pipelines; when wrapping a CLI binary with checksum-pinned downloads and nightly escapes; when projecting a standard report format (SARIF) into native platform outputs (checks/annotations, MR comments, job summaries); or when committing machine-authored changes back to PRs safely. Source code and direct tests are ground truth; references carry decisive excerpts and graph retrieval.

## Capsule map
- **Arg surface** — `dual-format-arg-parsing`: shell-quote tokenization with env expansion off → four comma heuristics → legacy re-parse + deprecation warning; `--property` values rejoin commas. `env-input-surface`: QODANA_* namespace, default-aware boolean parse (`value !== 'false'` vs `value === 'true'`), within-docker=false injection unless QODANA_DOCKER set.
- **CLI lifecycle** — `pull-args-filtering`: extractArg whitelist (-l/--image/-i/--config), first-match adjacent-token semantics (equals-form blind spot). `cli-provisioning-checksums`: cli.json platform×arch table, verify-except-nightly, version-scoped tool cache, use-installed-cli probe.
- **Caching** — `native-cache-partitioning`: `native-${bool}-` prefix stamped on BOTH keys keeps restoreKeys fallback intra-mode only. `cache-save-skip-contract`: success gate → default-branch gate → reserved-key equality skip → saveCache with string-matched already-exists race catch. `host-cache-compensation-plane`: GitLab (no cache primitive) mirrors user-visible `.qodana/cache` to/from cacheDir with path.resolve equality guards both directions — copy in before scan, force-cpSync back after publish; VSTS has no caching at all; gitlab gate is inline `useCaches && (Success || FailThreshold)`.
- **PR mode** — `pr-base-resolution`: QODANA_PR_SHA env → fresh fetch+merge-base (stale-webhook-sha workaround) → payload-sha merge-base → empty string disables PR mode, never throws. `merge-commit-pr-warning`: `%P` parent-count ≥2 detector, advisory-only warning with per-host remediation hints.
- **Orchestration** — `orchestrator-phase-structure`: concurrent [reaction+prepareAgent+restore] → single NONINTERACTIVE exec → concurrent [push-fixes+artifacts+gated-cache-save+publish] → exit-code-preserving setFailed distinguishing FailThreshold(255).
- **Output** — `sarif-output-projection`: baselineState filter, error/warning/*→failure/warning/notice ladder, null-location skip, 50-cap check batching, Checks-API→core.* fallback. `markdown-report-assembly`: section pipeline w/ count-sorted severity table, diff-fence vs colored-span coverage conclusions, SILENT license drop over truncation at platform limits (65k/65336/150k). `sarif-uribaseid-resolution`: recursive base-id chaining with visited-set cycle guard → `''`, trailing-slash normalization before artifact append, literal `%NAME%` tokens, degrade-not-throw contract. `check-run-upsert-lifecycle`: publishGitHubCheck does listForRef→find(name)→update:create keyed on (name, PR head sha) with immediate status:'completed' — this name-keyed identity is what makes 50-annotation batching idempotent. `sarif-side-channel-extraction`: coverage/sanity ride runs[0].properties with SARIF-native thresholds defaulting 50; degradation is deliberately asymmetric — coverage zero-fills on missing property but THROWS on missing file, sanity always returns 0.
- **Interaction** — `comment-upsert-tagging`: hidden `<!-- @vVERSION : tool, dir -->` idempotency key, find→update/create, thread resolve/status where supported. `reaction-swap-protocol`: create-first captures own login as identity, paginate + content∧author-filtered delete.
- **Write-back** — `quickfix-push-pipeline`: identity→add→commit(gated=done)→rebase(gated=abort)→branch/cherry-pick→push with ci.skip/[skip-ci] loop suppression, validateBranchName charset guard.
- **Build tools** — `build-tool-plugin-twins`: Installer.setup verify-or-redownload loop, TeeOutputStream sentinel mining ("Inspection run is terminating"), orb bash twin with pinned sha256.
- **Architecture** — `platform-adapter-fanout`: pure common/ core + named-identical duplicated adapters (same verb set per utils.ts); copy-closest-then-swap-mechanics over interface extraction. `version-doc-tests`: regex-extract every version mention from docs, require ≥1 and exact-equality against VERSION (major-only where the consumer resolves by major).
- **Release plane** — `release-checksum-sync-kernel`: one update-cli.js pass rewrites cli.json checksums (allowlist-gated keys), appends a version row to generated Checksums.kt, positionally overwrites the orb `QODANA_SHA_256` line (:56), and cascades full/minor/major sed replacements repo-wide EXCLUDING Checksums.kt (history must survive for old pins). `per-host-publish-divergence`: three publishOutput twins share the getSummary pipeline and diverge in exactly four load-bearing places — useDiffBlock true/true/false (Azure can't render diff fences), gitlab-only `isPrMode && postComment` comment gate, vsts always-on postSummary + GitHub's four-way Promise.all fan-out, uniform warn-don't-fail catch posture; toolName derives from splitting the shared title on `'found by '`.
- **Transport** — `single-binary-execution-transport`: hosts never compose docker commands; the CLI decides mode from `--ide`/`--within-docker[=]false`; adapters owe `NONINTERACTIVE=1`, per-host PR gates appending `--commit <sha>`, branch identity env (scan QODANA_REVISION always; vsts/gitlab QODANA_BRANCH PR-only), ignoreReturnCode/never-reject exit plumbing; gitlab spawn resolves 127 on missing binary / 1 on signal kill; pull phase owned by scan+vsts only and its failure never aborts scan.
- **Artifacts** — `report-artifact-publication-triples`: shared JSZip kernel (0777 entries, DEFLATE stream, sibling-of-results zip) feeding three postures — @actions/artifact upload; Azure container 'Qodana' PLUS `qodana.sarif.json`→`qodana.sarif` rename into CodeAnalysisLogs; GitLab plain cpSync into `$CI_PROJECT_DIR/.qodana/results` (RESULTS_DIR override); all execute-gated warn-don't-fail.

Adapt host-specific mechanics: toolkit calls (@actions/* vs gitbeaker vs azure-devops-node-api), env-variable names, PR-mode gates and branch-identity env, artifact store calls and platform-magic names (CodeAnalysisLogs, extension-less qodana.sarif), comment storage (issues vs discussions vs threads), credential injection paths, per-host char limits and help text. Omit product surface: JetBrains-specific branding/contact blocks, the checked-in vsts/QodanaScan bundle (regenerated dist), GitHub Pages report hosting flows, Qodana Cloud registration UX, tag.yml floating release branches (repo's own git ops, not a porting contract).
