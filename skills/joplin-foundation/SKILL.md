# joplin: offline-first sync kernel

## Use this for
Use when building or porting a multi-device sync engine over "dumb" storage targets (file systems, WebDAV, S3): lease/lock protocols without atomic test-and-set, cursor-based delta pagination, deletion pipelines that cannot cascade wrongly, last-writer-wins metadata merging across disconnected clients, and conflict handling that preserves both sides. Source code and direct tests are ground truth; references carry decisive excerpts and graph retrieval.

## Capsule map
- **Lifecycle** — `sync-lifecycle-choreography`: single-flight start guard, best-effort auxiliary services vs hard-fail info plane, execution order delete_remote → update_remote → delta despite comment numbering, cooperative cancel points, outputContext = delta cursor only.
- **Mutual exclusion (dormant)** — `dormant-lock-kernel`: `enabled_ = false` with 7 disabled short-circuits and no production setter; nullLock sentinel contract; locks/ + temp/ dirs must exist before enable. `file-lock-two-phase-acquire`: lock filename `<type>_<clientType>_<clientId>.json`, two-pass write-read-back for shared locks, write-recheck spin + oldest-first deterministic winner for exclusive locks, same-client sync-lock takeover option. `autolock-refresh-expiry`: 60s heartbeat vs 180s TTL, terminal expiry (never silently re-acquire), errorHandler owns timer teardown and flips the target-locked flag.
- **Target state plane** — `syncinfo-lww-merge`: `{value, updatedTime}` envelope, enabled-beats-used master-key ladder, timestamp-0 bootstrap semantics, dangling activeKeyId clear, forward-compat app floor refusal. `target-version-migration-ladder`: outdatedClient/outdatedSyncTarget gates, exclusive-locked ladder aborting on lost lease both before AND after each step, legacy info.json rewrite only for v1/v2.
- **Outgoing changes** — `upload-action-loop`: full-content fetch as the trusted clock, action matrix (CreateRemote/UpdateRemote/three conflict classes), future-dated vs force_sync vs changedDuringSync classification, blob-upload skip when blob_updated_time ≤ sync_time. `preupload-batch-cache`: never-synced items bulk-uploaded via multiPut, cache hit only on exact updated_time equality, resources and oversize items excluded, batch errors replayed per item.
- **Incoming changes** — `delta-context-pagination`: driver cursors + supportsDeltaWithItems fast path, download TaskQueue, checkSyncTargetIsValid after each page, cancelled runs keep the OLD context, statsCache/statIdsCache stripped before persisting. `basicdelta-failsafe`: high-water timestamp + same-millisecond tie set, binary-search deletion detection, ≥90% deleted ⇒ 'failSafe' abort, deletedItemsProcessed latch cleared on final page.
- **Deletion & conflict** — `delete-pipeline-folder-last`: deleted_items ledger rows removed immediately on success, batch-of-20 with methodNotSupported fallback, read-only refusal re-downloads (undelete), folders deferred to loop end and only deleted empty else markNotesAsConflict. `conflict-triage-ordering`: non-notes take remote wholesale (folder children guarded), note conflicts gated by title/body/encryption difference, conflict-note linked only AFTER the remote-overwrite save rebuilds sync_items.
- **Failure surface** — `error-taxonomy-tail-resync`: six info-grade codes vs changedDuringSync-as-non-error vs retryable-transport-unreported, always-idle epilogue, tail itemsThatNeedSync re-schedule as the very last step. `remote-clock-discipline`: remote mtime for leases, payload embedded updated_time for content freshness, local clock only for >now+1Day impossible-state throws.
- **Transport & adaptation plane** — `synctarget-registry-platform-composition`: empty-until-composed id-keyed registry, four platform composition roots register different subsets, throw-on-unregistered names, OS filtering, pinned optionsOrder. `basesynctarget-lazy-wiring`: lazy memoized fileApi()/synchronizer(), started/ready/error polling latch, service injection post-construction, setFileApi test sharing. `file-api-minimum-contract`: put/get/stat/mkdir/list/delete minimum pinned by a shared conformance suite, idempotent initialize hook called once per sync run, tempDirName must be set or the clock probe throws. `transport-retry-ladder`: tryAndRepeat opt-in count (WebDAV=3 hardcoded, default 0), five non-repeatable codes, shim fetch retries suppressed to one owner. `remote-clock-offset-probe`: midpoint temp-file estimator, 10-min TTL cache behind a double-checked mutex, fail-soft zero-offset degradation feeding LockHandler lease math. `driver-delta-two-tier`: dumb drivers adapt listings into shared basicDelta, JoplinServer runs native cursors with locks/temp/.resource filters and resyncRequired→restart, OneDrive's native delta quarantined as delta_BROKEN, getSupportsDeltaWithItems sniffs embedded payloads.
