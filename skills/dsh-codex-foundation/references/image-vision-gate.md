# Shared image vision gate — how does a tool that returns image blocks gate on the CURRENT conversation model's modalities without duplicating logic across tools?

## assertImageCapable
**Path/Symbol:** `src/image-capability.ts:5-20 assertImageCapable` (whole module is this one function).
**Signature:** `export async function assertImageCapable(ctx: Context, exec: ToolExecution, action: string): Promise<void>` — throws instead of returning a verdict.
**Data Shape:** inputs are the Cordis context (for `ctx.llm.resolveModelInfo`), the host tool execution (`exec.agent`, `exec.signal`), and an action verb interpolated into both error messages. Resolution order for the model route: `exec.agent?.session.requestHeader()?.config` first, then `exec.agent?.options.provider` / `exec.agent?.options.model`. No output on success.

### Decisive source
```ts
const configured = exec.agent?.session.requestHeader()?.config
const provider = configured?.provider ?? exec.agent?.options.provider
const model = configured?.model ?? exec.agent?.options.model
if (provider === undefined || model === undefined) {
  throw new Error(`cannot ${action}: the current model route is unavailable`)
}
const info = await ctx.llm.resolveModelInfo(provider, model, exec.signal)
if (info.inputModalities === undefined || !info.inputModalities.includes('image')) {
  throw new Error(`cannot ${action}: model "${model}" does not declare image input`)
}
```

**Flow:** read the session's live request header config → fall back to agent options per field → throw route-unavailable if either coordinate is missing → resolve model info asynchronously WITH the caller's abort signal → refuse unless `inputModalities` is defined AND contains `'image'`.
**Invariant:** unknown modality information fails closed (`undefined` modalities ≠ image-capable); the gate runs before provider fetches and before conversation-history mutation in both consumers, so a refused tool call leaves no generated bytes or attachments behind; error messages carry the action verb and model id but never credentials or session secrets.
**Probe:** `tests/imagegen.spec.ts:220-230` — imagegen for `'gpt-5.3-codex-spark'` errors with `does not declare image input` and `fetchMock` is NEVER called; `tests/read-image-enhancement.spec.ts:178-185` — enhanced `read_image` URL path produces the same message. Both tools share this exact module (trace: `assertImageCapable` inbound callers = `imagegen.execute`, `read-image-enhancement.execute`).

## Verdict
Adopt one module-level async gate consumed by every image-producing tool, header-config-first resolution, fail-closed modality checks, and signal-forwarded capability lookup. Adapt the host lookup API (`resolveModelInfo`) and where the "current model" lives in your agent runtime. Omit per-tool copies of the check — the whole value is that imagegen and read_image cannot drift.
