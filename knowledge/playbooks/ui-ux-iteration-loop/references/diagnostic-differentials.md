# Diagnostic Differentials for UI/UX Symptoms

A behavior is not a diagnosis. Use this reference when several psychology labels could explain the same observation. Record the observation without theory, list at least two plausible explanations, then run the cheapest probe that separates them.

| Observed symptom | Plausible explanations | Disambiguating probe | Avoid |
|---|---|---|---|
| Primary action is missed | weak visual salience; attention fixed elsewhere; label has weak information scent; action appears unavailable | ask for the next action without prompting; record gaze/first click only if available; test label and placement separately | calling every miss “change blindness” |
| User pauses before choosing | options are hard to compare; consequence is unclear; commitment feels risky; task is low priority | ask the user to explain differences and expected consequences; inspect reversibility and trust signals; compare decision accuracy, not speed alone | assuming fewer choices always wins |
| User abandons a form | required effort exceeds value; privacy concern; validation/recovery failure; interruption; technical defect | inspect field-level drop-off and errors, then observe a realistic attempt and ask about the moment of exit | inferring motivation from funnel location alone |
| User repeatedly goes back | recall burden; missing comparison support; weak orientation; fear of losing state | note what information is sought on return; keep that information visible in a reversible variant | treating all backtracking as failure—comparison may require it |
| User ignores instructions | selective attention; poor timing; low relevance; unfamiliar vocabulary; instructions are too costly | present guidance at the decision point; ask for teach-back; compare errors and comprehension | adding louder or longer instructions first |
| User chooses the default | default is genuinely suitable; inertia; perceived recommendation; fear of changing it; option differences are unclear | ask what the default means and whether it was noticed; test transparent consequence and easy reversal | reporting default uptake as preference |
| Faster completion | lower effort; skipped comprehension; accidental path; premature submission | pair time with correctness, confidence, recovery, and downstream reversal | treating speed as success by itself |
| More clicks or time | productive engagement; confusion; comparison; recovery work; instrumentation change | inspect path sequence and outcome quality; segment new versus experienced users | treating engagement volume as user value |
| High satisfaction with errors | aesthetic-usability halo; politeness/observer bias; low expectations; task was unrealistic | compare observed success and delayed recall with rating; use neutral prompts | allowing preference to overrule behavior |
| Users blame themselves | poor feedback or mapping; hidden system constraint; learned helplessness; true knowledge gap | ask what they expected before revealing the system model; inspect whether recovery teaches the right rule | accepting “user error” as root cause |
| Repeated feature use | durable value; habit; forced workflow; addiction loop; lack of alternatives | ask whether use was intended and controllable; inspect exit, disable, and regret measures | equating retention with wellbeing |
| Trust collapses late | early credibility problem; commitment requested too soon; surprise cost/data use; failure during a high-stakes moment | identify first trust-relevant cue and requested commitment; test disclosure comprehension and recovery | solving trust with decorative badges alone |

## Differential procedure

1. Write the earliest consequential behavior in observable terms: actor, context, action, system state, and consequence.
2. Separate **ability**, **attention**, **comprehension**, **memory**, **motor effort**, **motivation**, **trust**, and **technical reliability**. Do not collapse them into “cognitive load.”
3. Name two or three mechanisms that predict different evidence. Include a nonpsychological explanation such as latency, copy ambiguity, missing capability, or instrumentation error.
4. Choose a probe that could make the preferred explanation lose: teach-back for comprehension, first-click for scent, forced-state testing for reliability, comparison task for choice, delayed recall for memory, or path analysis for effort.
5. Change one coherent cause. A coherent intervention may include copy, focus, placement, announcement, and preserved state when those parts jointly create one usable behavior.
6. Record what the result rules out. If the evidence does not discriminate, lower confidence and design a better probe instead of renaming the law.

## Segmentation checks

Before generalizing, check whether the mechanism plausibly differs by novice/expert status, device and input mode, language and reading direction, disability and assistive technology, interrupted versus focused context, trust relationship, frequency of use, and stakes. Segment only from a prior hypothesis; do not mine slices until one metric looks favorable.
