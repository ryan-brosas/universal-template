# Psychology Lenses for UI/UX Diagnosis

Use this as a diagnostic map, not a menu of effects. Start with observed behavior, select a plausible mechanism, and test an intervention. Several mechanisms can predict the same symptom; a label does not establish causality.

| Lens | Observable signal | Plausible mechanism | Small intervention | Evidence probe |
|---|---|---|---|---|
| Attention | Important status/action is missed; change goes unnoticed | Selective attention, tunnel vision, change blindness | Put feedback near current focus; preserve it long enough; use restrained contrast or motion | First-click test; task observation; notice/recall question without prompting |
| Gestalt grouping | Users pair the wrong label/control or mistake separate regions as one | Proximity, common region, similarity, connectedness, figure/ground, continuation | Tighten within-group spacing; enlarge between-group spacing; make affordances perceptually distinct | Ask users to identify groups and expected action before interacting |
| Working memory | Backtracking, repeated comparison, forgotten requirements | Recall burden, unchunked information, unstable spatial placement | Keep requirements and prior values visible; chunk by meaning; support recognition and external memory | Count revisits, memory-dependent errors, and cross-screen comparisons |
| Sensemaking | Wrong first click; confusion about labels or system behavior | Mental-model mismatch, weak information scent, costly information foraging | Use familiar language and placement; expose consequence and destination; strengthen scent | First-click success; path length; “where would you go?” explanation |
| Choice | Hesitation, arbitrary selection, abandonment among options | Choice effort, loss aversion, satisficing, anchoring, framing, sticky defaults | Remove irrelevant options; show meaningful differences; order by task; make defaults transparent and reversible | Decision time, option comprehension, regret/reversal, segment outcomes |
| Motor interaction | Missed taps, accidental destructive action, slow target acquisition | Target too small/distant; high physical interaction cost | Enlarge hit area; place frequent actions near use; separate dangerous controls | Mis-tap rate, keyboard/touch completion, target-size check |
| Motivation | Avoidance, shallow engagement, dependence on reminders | Low autonomy, competence, or relatedness; effort exceeds perceived value | Provide choice, progress and useful feedback; remove needless work; support resumption | Voluntary return, completion, qualitative confidence—not raw time-on-app alone |
| Practitioner bias | Team overweights one quote or defends its design | False consensus, confirmation, availability, halo, anchoring, framing, functional fixedness | Separate observations from interpretations; seek disconfirming cases; blind or randomize where practical | Competing hypotheses, negative cases, neutral survey wording, reviewer diversity |
| Persuasion and trust | Privacy hesitation, price surprise, refusal to commit | Trust has not matched requested commitment; authority/social proof/scarcity cues alter judgment | Ask progressively; explain data use; show verifiable evidence and honest terms | Comprehension, trust interview, complaint/refund/cancellation and conversion together |
| Emotion and delight | Strong first impression but poor completion, or functional success feels brittle | Visceral, behavioral, and reflective responses differ; peak and ending dominate memory | Fix utility and recovery first; then refine first impression, peak moments, and ending | Task success plus post-task confidence and later recall |
| Technology attitude | Users become distracted, trapped, anxious, or over-attribute intelligence | Vortex effects, prior concerns, anthropomorphism/ELIZA effect | Protect task focus; make exit/control obvious; state automation limits | Unplanned detours, exit success, expectation calibration, wellbeing feedback |

## Interpretation rules

1. **Behavior before theory.** “Users missed the update” is evidence; “change blindness caused it” is a hypothesis.
2. **Recognition beats recall, but visibility has a cost.** Expose task-critical information; progressively disclose rare complexity without hiding prerequisites.
3. **Consistency compounds learning.** Spatial and interaction stability builds memory. Break convention only for a measured gain.
4. **Defaults are choices made by the system.** Make their consequences clear, suitable for most users, and easy to change.
5. **Negative events weigh heavily.** Prevent loss, preserve input, explain errors, and provide recovery before adding delight.
6. **Aesthetics can bias perceived usability.** Attractive treatment is valuable, but never use preference ratings as a substitute for task success.

## Ethical gate

Persuasion is acceptable only when the user can understand the material choice, decline without disproportionate friction, reverse where feasible, and obtain the outcome they intended. Reject false scarcity, disguised ads, hidden recurring costs, confirm-shaming, sneaking, forced continuity, obstructed cancellation, and engagement loops that work against user welfare. Measure downstream regret, complaints, refunds, and trust—not conversion alone.
