# Website inspiration that informs decisions

Use for redesign inspiration, organizing a reference library, or “go deeper”
before choosing a visual direction or building a design system. Depth means
resolving a design question, not increasing the screenshot count.

## 1. Separate the evidence purposes

Keep the current-site audit distinct from external inspiration. The audit
establishes existing content, behavior and constraints; it is not automatically
the redesign target. Move or relabel misplaced references without destroying
baseline evidence. An explicitly requested before/after comparison can include
both, clearly identified. Reusing source assets later is a separate decision.

## 2. Give each comparison a question

Organize by the visitor's job and relevant page pattern, not only by brand or
homepage. Ask, for example, whether someone needs description-rich cards or
aligned comparison facts. Choose contrasting mechanisms for that question.
Keep visual tone separate from task structure: borrowing a table's hierarchy
does not select its palette or imply the competitor's product capabilities.

Reuse useful captures. Add a source only for a missing comparison or state.
A typography moodboard need not expand into a full interaction study.

## 3. Trace context → anatomy → behavior

| Level | Evidence to inspect | What it answers |
| --- | --- | --- |
| Page | Entry, information order, primary action, surrounding navigation | What job does the page support? |
| Part | A faithful crop with labels, units and control boundaries intact | Which facts and actions belong together? |
| State | Actual before/action/after, such as query/results/empty or closed/open | What changes, persists, or permits recovery? |

Retain full-page context for each crop. Trim between complete rows rather than
cutting through values or controls. Where sequence matters, follow real
transitions on one source; screens from different sites are alternatives, not
proof of a continuous journey. Label untested behavior instead of drawing it
into existence. Captures from separate visits are state studies, not an
uninterrupted journey. Compare outcomes only when relevant inputs match;
otherwise label the changed assumptions.

Ask what should persist across a handoff: product identity, calculated assumptions
or example preference. End with the observed mechanism, a proposed adaptation or
rejection, and unresolved product facts. A source's behavior or measured spacing
is not automatically a requirement for another product.

## 4. Preserve the evidence boundary

Before a probe, name its question, expected observable result and stop condition.
Capture start → action → result. Wait for a specific postcondition: requested
values populated, selected tab and code agreeing, or the panel fully visible.
Check that it actually became true; exhausting a wait loop is not success. Label
the observed state, not merely the attempted action.

Confirm that a detected popup, overlay or dialog is the region you asked for,
not just the first element a broad selector matched; check its own heading or
content. If a saved capture turns out to show a different but still useful state,
relabel it to what it actually shows and note the correction instead of keeping
the hopeful label.

Inspect the image alongside semantic/focus evidence before importing it. These
reads may sample different animation frames. If they disagree, check the settled
state rather than diagnosing a defect from the transition. After a timeout,
inspect saved artifacts before replaying work. Retry only to resolve a named
uncertainty within the research budget; otherwise exclude the unusable capture
and record the gap. Inspiration need not become third-party debugging.

Record URL, available capture time, viewport, action/state and crop origin.
Disclose changed capture conditions, such as reduced motion. If metadata fails
but the image survives, retain only supported visual claims. A copy icon does
not prove copying; dismissal does not prove focus restoration; one keyboard
transition is not an accessibility pass. Competitor claims remain attributed.

Reference images and cloned frames are not linked component masters or tokens.
Uninspected source libraries are unknown, not absent.

## 5. Organize and verify at two scales

Reuse the library's presentation frames and move existing references rather than
rebuilding them merely to change order. Keep source/state labels readable. If the
canvas must stay visual-only, put longer rationale in the agreed notes owner.

- **Within each board:** inspect text, crop boundaries, alignment, overlap and
  clipping. Use content-fitting containers when changed image heights overflow.
- **Across the canvas:** read final board bounds after content changes; check
  ordering, gaps and rectangle intersections. Recompute placement from those
  bounds, not stale heights. An individually clean render cannot prove that
  neighboring artboards do not overlap. Inspect an overview when available;
  if unavailable, report numerical placement checks as such, not visual review.

## Stop before premature system-building

Return a decision-ready shortlist: useful mechanisms, tradeoffs, evidence and
remaining questions. Untested states stay gaps, not implied coverage. Research
alone does not establish usability, accessibility or component linkage. Source
asset/token inspection and authorized design work are later boundaries, not
side effects of finishing the reference library.
