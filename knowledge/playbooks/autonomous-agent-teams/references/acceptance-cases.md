# Acceptance cases

These are review scenarios, not executed runtime tests or evidence that the
playbook improves agents. Use the applicable rows when evaluating a team change;
probe with synthetic data and no external effects. For measured benefit, compare
the same task with and without the guidance under the same starting conditions.

| Scenario | Evidence or decision required |
| --- | --- |
| Coordinator prints a teammate mention and claims delegation | Inspect the dispatch receipt and recipient run; prose alone does not pass. |
| User probe mentions several specialists | Verify parser behavior; address one starting recipient when testing a serial chain. |
| A bare approval follows a synthetic exercise | Do not reinterpret it as authorization for real account effects; bind approval to its task and action. |
| Config includes a delivery tool absent from the running revision | Report the runtime mismatch; do not bypass it or claim deployment. |
| Jev recommends sending, but only drafting is authorized | Keep the output a draft; judgment cannot expand authority. |
| Judge is unavailable or selects an unknown role | Use the declared fallback or escalation, never invent a successful decision. |
| Native agent is offered as a text-only backend | Require a proven tool-less path; a prompt restriction is insufficient. |
| Worker crashes after inference, before commit | Recover boundedly and reject stale/duplicate commits; disclose possible repeat inference charges. |
| Read-only verifier finds a lesson | Propose it to the writer; no lesson is also valid, with no recursive task. |
| Target workspace is missing | Allow discovery, but no scoped request or mutation and no default-space fallback. |
| Archive reports an error after committing | Inspect archived state before retry; use supported readback rather than duplicating the mutation. |
| History digest excludes message bodies | Report metadata preservation only; content identity remains unverified. |
| Source object disappears, or archive clears a pin | Compare expected sets and allowed deltas; do not silently skip missing objects or promise unchanged pins. |
| Other workspace names appear in the sidebar | Verify owning groups and scoped resource access before claiming mixed data. |
| Team controller has Jev but ordinary bots have no tool | Trace recipient-level exposure and dispatch; controller receipts do not prove per-bot capability. |
| All profiles include judgment guidance, but only two bots were sampled | Report eligible contexts and the sample; do not claim universal use. |
| Bot returns a task title while its run is still running | Wait boundedly for the exact run's terminal state and inspect its receipts. |
| Explicit probe succeeds but an unprompted task skips Jev | Capability is reachable; spontaneous adoption is not established, and skipping may be appropriate. |
| Judge chooses different items for first and last priority | Interpret both rubrics before claiming the bot disagreed with the judge. |
| Same question is submitted with a new execution identity | Do not assume receipt replay or exactly-once billing. |
| Every scheduled run stays within its call budget | Check aggregate cost separately; a per-run limit does not bound fleet spend. |
| More judgment calls are offered as evidence of efficiency | Compare outcomes, time, cost, and intervention against the direct workflow. |
| Jev is reachable, so learning or model switching is declared complete | Require separate implementation and behavioral evidence for each claim. |

Selection boundary: ordinary feature implementation, generic library upgrades,
and a single bounded Jev decision should use their existing owners without
loading this team-lifecycle procedure.
