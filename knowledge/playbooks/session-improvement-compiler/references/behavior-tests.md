# Examples

Optional illustrations of the judgment, not a suite, checklist, or scoring system.
Usable guidance a future task can actually find beats more rules.

| Experience | Useful outcome |
|---|---|
| A technique, recovery, or bounded diagnostic a future agent would otherwise rediscover | Keep its trigger and the technique itself; skip anything source, tests, or Git already answer |
| A defect or unfinished implementation noticed while compiling | Report it as a finding; fixing it needs its own authorization |
| A local constraint from one project or client | Keep it with that project; do not generalize it into shared guidance |
| A method the relevant playbook already covers | Confirm and cite that owner instead of adding a duplicate |
| An observation that only seems useful right now | Let it go; no repository digest or new note |

Reflect and recall requests answer without editing. A compile request should produce
usable, discoverable guidance, or an honest "nothing worth keeping". Do not block on
an unavailable history provider when the session events already suffice.
