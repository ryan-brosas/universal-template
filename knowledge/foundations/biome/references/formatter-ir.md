# Formatter IR — how do you encode formatting as a flat element stream with best-fitting groups, fills, interning, and source maps?

**Source:** Biome MIT `main@6cd32636f463551b8dfe46aeefb1191d437b4694`; Codebase Memory `biome` (full mode, 141,682 nodes / 644,530 edges, generation 2026-08-16). **Question:** a formatter needs a language-agnostic intermediate representation that is small, memoizable, and prints with Prettier semantics. What is Biome's IR and its fits/BestFitting/Fill/interning/source-map machinery?

## The formatter-IR seam
**Path/Symbol:** `crates/biome_formatter/src/` — `format_element.rs`, `format_element/{tag.rs, document.rs}`, `printer/{mod.rs, queue.rs}`, `buffer.rs`, `formatter.rs`, `source_map.rs`, `builders.rs`, `macros.rs`.
**Signature:** `enum FormatElement` (format_element.rs:29-118); `Tag` start/end pairs (tag.rs:8-77); `Printer::print`; `BestFittingVariants`; `Fill`; `Interned`; `TransformSourceMap`.
**Data Shape:** the whole vocabulary is ONE enum `FormatElement` — Space/HardSpace, Line(LineMode), ExpandParent, SourcePosition, Token{&'static str}, Text{Box<str>}, LocatedTokenText, Mapped*, LineSuffixBoundary, Interned, BestFitting. Structure is expressed NOT by nesting but by `Tag` start/end pairs streamed inline (Indent, Align, Dedent, Group{id, Cell<GroupMode>}, ConditionalContent, IndentIfGroupBreaks, Fill+entries, LineSuffix, Verbatim, Labelled, Embedded). Size is enforced: `static_assert!(size_of::<FormatElement>() == 24)` (:652-659); Tag is 16 bytes; Align payloads boxed to keep one pointer wide (tag.rs:262-264).

**Text width** is precomputed ONCE at construction (ASCII fast path byte-by-byte; unicode_width on a `#[cold]` slow path; `'\n'` → Multiline marker) and stored value+1 in `NonZeroU32` so `Option<Width>` stays u32-sized (:355-424). Group mode mutability uses `Cell<GroupMode>` so `propagate_expand` flips Flat→Propagated in place through shared refs (tag.rs:151-197).
**Best-fitting groups:** on `StartGroup` the printer decides flat vs expanded (:262-296): propagated-expanded prints expanded; a cached fits-verdict stays flat; otherwise it sets `measured_group_fits`, registers Flat, pushes a frame, and runs `fits()` — a SHADOW REPLAY of the remaining queue on top of the real PrintQueue without consuming it (queue.rs:157-166: "The queue is a view on top of the [PrintQueue] because no elements should be removed while measuring"), simulating line-width accumulation up to the first hard break. The verdict cache invalidates at every emitted newline (:851-855). One rule surprises everyone (:1262-1312): even in flat mode, content DIRECTLY containing a hard/empty line returns Fits::Yes — "since that break is always going to exist, regardless of the print mode" (leading-comment example; "most comments inline for fills are used to separate _groups_ rather than to single out an individual element"). Forward references degrade gracefully during fits (unwrap_or_else(mode)) but PANIC in real print.
**BestFittingVariants:** N hand-authored layouts ordered most-flat-first, most-expanded-last (:407-475). Print tries each except the last via fits(), committing to the first that fits; none fits → last expanded (:533-600). Inside fits, BestFitting collapses to most_flat (flat) or most_expanded (expanded). Cost model (macros.rs:296-320): "multiple representations of the same content... worst case complexity is that the printer tries each variant. This can result in quadratic complexity if used in nested structures." Variants act as expansion BOUNDARIES for propagation (document.rs:44-130); `will_break()` inspects only most_flat. Constructor is `#[doc(hidden)] unsafe` purely as API friction (:443-450).
**Fill:** alternates StartEntry/EndEntry items with separators (:608-740). Each round classifies via `FitsMeasurer::new_flat` into FillPairLayout (:861-882): Flat / ItemFlatSeparatorExpanded / ItemMaybeFlat / Expanded. Priority (:608-618): "first expand the *separator* if the content exceeds the print width and only fallback to expanding the *item*s" — preserving trailing-comma style (break AFTER the comma). The hard case — ungrouped fill entries with hard lines from leading comments — gets the extensive rationale at :1262-1312 (must_be_flat would wrongly isolate the element). Optimization avoids re-measuring the next item twice (:648-652).
**Interning:** `Interned` wraps `Rc<[FormatElement]>` with POINTER-based equality/hash (:255-270) — manual interning, not content-hash dedup. Consumers memoize per-interned work keyed by pointer: `propagate_expand` caches expansion verdicts in `FxHashMap<&Interned, bool>`; RemoveSoftLinesBuffer keeps an original→cleaned cache. The deepest failure-mode comment (:88-125): interned lists cache their expansion verdict based on `expands` AT THE END of iterating children — so a best_fitting after the last expanding element could set expands=false wrongly. Fix: DON'T reset expands=false at best_fitting boundaries. Regression test `interned_best_fitting_allows_sibling_expand_propagation` (:993-1040) fails if the reset returns. Pointer-keyed caching is sound precisely because interning is manual — equal-looking documents may differ in group modes.
**Source maps:** two fidelity layers. Printer→output: SourcePosition/Mapped* carry TextSize offsets; print_text emits SourceMarker {source,dest} BEFORE AND AFTER each token (:415-455); markers DEFERRED (:299-306: "Pushing the marker now would mean that the mapped range includes the indent range... Queue the source map position and emit it when printing the next character."); literal line breaks get dual markers mapping one source byte onto multi-byte CRLF (:461-476). Transformed-tree→original: `TransformSourceMap` stores DeletedRanges sorted by transformed_start with cumulative preceding-lengths (:33-36) — O(log n) binary-search lookup with out-of-order tolerance (line-suffix comments print late, :186-235); `extend_trimmed_node_range` widens trimmed ranges so verbatim nodes re-include removed parens. Debug asserts catch implementation bugs ("deleted bytes exceeding source offset is a bug in the source map implementation").
**Invariant:** FormatElement is exactly 24 bytes (static_assert); fits is a shadow replay (never consumes the queue) with verdicts invalidated at every newline; BestFitting is an explicitly-discouraged last resort with a documented quadratic cost; interning is pointer-identity so memoization must not reset early-exit flags at boundaries; source maps are deferred per-token markers + compressed deleted-ranges, never per-token full maps.
**Probe:** `cargo test text_width` (width("a\tb")==6 with indent 4, width("a\nb")==None, CJK width 6, zero-width-space width 2); printer tests ~1690+ (four array items fit one line; nested indentation renders 2-space levels); macros doctest (~155-215) prints the same doc at widths default/21/20 yielding three progressively exploded layouts; `cargo test interned_best_fitting_allows_sibling_expand_propagation`; companion `literal_line_break_is_forced_without_propagating_expand`; `cargo test source_map` — '(a + (((b + c)) + d)) + e' → 'a + b + c + d + e' incl. out-of-order insertion; '((a));' trimmed query 'a' resolves to '((a))' after chained widening; formatter.rs fill doctests (:160-203).

## Verdict
Adopt the flat 24-byte element stream with paired inline tags, shadow-replay fits with newline-invalidation, BestFitting flat-to-expanded with explicit cost warning, separator-first Fill, pointer-identity interning with boundary-reset audit, and deferred-marker + compressed-deleted-range source maps; adapt element vocabulary and width rules per language; omit Biome-specific tags (Verbatim/Embedded) unless needed. Coverage caveat: the fits/IR behavior is pinned by the in-file unit tests and doctests cited above; no separate integration test isolates the printer.
